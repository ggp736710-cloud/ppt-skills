# 单页措辞

把骨架上的每一页写成幻灯片上的字。页面上只留听众扫一眼能带走的判断；解释、过渡和防备追问放进备注。

## 先读什么

需要叙事骨架和汇报任务卡。只有单页题目时，也可以只写这一页，但要回读任务卡里的决定和已核实事实。两者都没有时，先问这一页要帮听众做什么判断。

## 页型写法

| 页型 | 页面上有什么 | 备注里有什么 |
|------|--------------|--------------|
| 封面 | 主题、汇报人、日期、场景 | 开场第一句，点明本次决定 |
| 总览 | 三件今天要讲的事 | 三件事和决定的关系 |
| 结果 | 1 个判断句 + 最多 3 个结果 | 口径、周期、个人角色 |
| 原因 | 判断句 + 最多 3 个原因，按影响排序 | 哪个原因可以展开讲 |
| 对照 | 比较维度名称，双方各不超过 4 个字的结论 | 不要在页面上写长段落解释 |
| 路线 | 推荐动作、时间范围、交付物 | 为什么不选另一条 |
| 计划 | 阶段名、负责人、完成标志 | 依赖谁、哪天开始 |
| 风险 | 风险、触发条件、退路 | 什么情况下停 |
| 请求 | 请谁、在何时、批准什么 | 若只批准一半，最小可执行版本是什么 |

## 处理规则

1. **字数。** 标题不超过 18 个字。每条要点不超过 22 个字。一页要点不超过 3 条。超了就删修饰，不把一句拆成两个半句。
2. **页面不写过程流水。** 「本周开了三次会」不是要点。要点写成变化或承诺，例如「交接清单从 4 项减到 1 项」。
3. **事实边界。** 只用任务卡里已核实的事实。需要数字但没有时，要点写成「数字待核实」，不要填 0 或「显著提升」。
4. **场景语气。**
   - 述职：用「我负责的范围」划清个人与协作。成绩页先写结果，再写动作。
   - 项目方案：路线页同时写出「不做」或「不选」的那一侧，避免只介绍推荐方案。
   - 投标：用客户的目标当主语，少用「我们领先」。对照页比较标准和交付，不点名贬低其他投标人。
5. **备注三行就够。** 一行讲这页唯一要让人记住的话，一行写可能被追问的口径，一行写接到下一页的句子。
6. **强调只标一处。** 每页只指定一个要放大的词或数字。没有已核实数字时，指定标题里的判断，不指定一个假数字。

## 输出格式

用户给了完整骨架就逐页输出；只给一页就只输出那一页。

```
# 单页措辞

- 场景：
- 本次决定：

## 第N页｜页型

- 标题：
- 页面要点：
  1.
  2.
  3.
- 只说不写：
  - 记住：
  - 口径：
  - 接到下页：
- 放大：
- 证据位：沿用骨架的证据类型；内容由证据编排填写，这里只留类型
```

## 输出要求

- 把全部内容页标题按顺序再读一遍，读出来应能复述本次决定。读不通就改标题，不要在文末解释为什么读不通。
- 要点必须是完整信息，不能是「加强协同」「持续优化」这类没有对象的话。
- 请求页写出人名或角色、动作、时间。缺时间就写「时间待定」，不写「尽快」。
- 不在这一步选择图表类型和色值。
- 若某一页没有足够事实支撑标题，标题降级为待核实，并在「口径」里写缺的事实。
