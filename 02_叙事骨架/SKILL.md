# 叙事骨架

把任务卡展开成可以直接写文案的页序。生成和逻辑检查在同一次完成，不另出一份「优化报告」。

## 先读什么

优先读取已确认的汇报任务卡。没有任务卡时，只列出缺失的决定、听众、时长、已核实事实，停止写页序。

已有旧大纲时，先把旧大纲映射到任务卡的「本次决定」上，再重排页序。能留下的页写明保留原因。

## 三种场景的默认页序

页序为默认骨架，按必讲内容增删，总页数服从任务卡的页数预算。

**述职**

1. 封面
2. 本周期判断：达成了什么、差在哪里
3. 目标与结果对照
4. 结果背后的关键动作
5. 未完成事项与原因
6. 下周期目标
7. 需要的决定（资源、授权或目标确认）

**项目方案**

1. 封面
2. 建议当场做的决定
3. 问题与不做的代价
4. 推荐路线
5. 放弃的路线及原因
6. 范围、周期、负责人
7. 预算与验收
8. 主要风险与退路
9. 请求批准的事项

**投标**

1. 封面
2. 客户目标与我方理解
3. 评分点或需求对应总表
4. 做法与交付物
5. 同类经验（只使用已核实案例）
6. 实施计划与人员
7. 风险、边界与售后
8. 为什么现在可以进入下一步
9. 请求（入围、谈判或试点）

封面和最后的请求页固定保留。内容页超过 8 页时，把其中一页改成「今天只讲三件事」，放在封面之后。这三件事必须能导向本次决定。这一页占用页数预算，不在预算外另加。

## 处理规则

1. **标题是判断句。** 用「夜班漏检集中在交接后 30 分钟」，不用「漏检分析」「项目介绍」「我们的优势」。
2. **一页一个判断。** 一个标题里出现两个结论，就拆成两页；两页都在重复同一个判断，就合并，并把被合并的信息降为备注。
3. **先决定，后过程。** 述职在前 3 页内写出达成与缺口；方案在前 2 页内写清建议选哪条路线；投标在前 3 页内写清客户目标是否被理解。过程细节靠后。
4. **证据先占位。** 每页标注证据类型：数字、对照、经历、类比、标准符合，或「这页不需要证据」。不在这一步编造证据内容。
5. **时间落到页。** 封面 20 秒，请求页 50 秒，内容页 45–75 秒。各页秒数相加，与任务卡时长相差超过 10% 时，删页或改秒数，不靠「讲快一点」消化。
6. **旧稿检查四项。** 重排旧大纲时逐页看：是否指向本次决定、标题是否为判断句、有没有听众不决策的背景页、结论是否被前面的页支撑。断点写在该页旁边，不单独再写一份诊断长文。
7. **投标多一张对应表。** 有评分点时，页序后附「评分点 → 页码」。没有评分点时保留空表，状态写待补。

## 输出格式

```
# 叙事骨架

- 场景：
- 本次决定：
- 时长 / 页数预算 / 本骨架页数：
- 今天只讲的三件事（超过 8 页内容页才写）：

## 页序

| 页 | 页型 | 判断句标题 | 这页只证明 | 证据类型 | 秒数 | 逻辑备注 |
|----|------|------------|------------|----------|------|----------|
| 1 | 封面 |  |  | 不需要 | 20 |  |

页型只用：封面、总览、结果、原因、对照、路线、计划、风险、请求。

## 标题连读

把内容页标题按顺序连成一段话。连起来不能导向本次决定时，改标题后再输出。

## 动过的旧页（仅当用户带了旧大纲）

| 旧标题 | 处理 | 原因 |
|--------|------|------|
|  | 保留 / 改写 / 拆开 / 并入第N页 / 删除 |  |

## 评分点对应（仅投标）

| 评分点或客户要求 | 落在第几页 | 状态 |
|------------------|------------|------|
|  |  | 已对应 / 待补 |
```

## 输出要求

- 每页「这页只证明」用一句话，不写三段说明。
- 逻辑备注只写例外：过载、缺少事实、与决定无关、与上一页重复。没有问题的页写「—」。
- 不输出逐页口播，不输出配色。
- 使用了任务卡以外的数字时，改成「待核实」并在逻辑备注标明。
- 结束时指出下一步：需要写文案的页交给「单页措辞」，标了证据类型的页交给「证据编排」。
