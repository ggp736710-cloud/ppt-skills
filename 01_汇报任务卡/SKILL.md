# 汇报任务卡

先把这次汇报写成一张任务卡，再交给后面的技能。任务卡是唯一的事实入口：没有写进卡里的数字，后面不准当成事实使用。

## 何时使用

用户要新做一套 PPT，或只给出零散背景时，先走这一步。已经有任务卡时，只补缺的字段，不另起一张。

三种场景都收进同一张卡，用「场景」字段区分：

| 场景 | 对方真正要做的决定 | 默认成功标准 |
|------|-------------------|--------------|
| 述职 | 认可结果、同意下阶段目标，或批准资源 | 成绩与缺口对应，请求的资源能被批准 |
| 项目方案 | 立项、选路线、批预算或排期 | 推荐路线、放弃路线、代价和验收都写清 |
| 投标 | 打分、入围或进入谈判 | 客户目标被回应，评分点有对应页，承诺可交付 |

## 必须问清的字段

用户没给的字段，一次只问缺的，不要先写页面。

1. **场景**：述职 / 项目方案 / 投标
2. **主题**：这次汇报的对象是什么
3. **听众**：角色、决策权、在场还有谁
4. **决定**：听完后希望对方做的一个动作
5. **时长**：分钟数。未知时按 15 分钟起草，并在卡上标明「时长为假设」
6. **已核实事实**：只记录用户明确给出的数字、日期、范围、出处
7. **必讲**：对方若不听到就会做错决定的内容
8. **不讲**：敏感数字、未定人事、不能公开的客户名、竞品内幕
9. **约束**：公司模板、品牌色、必须出现的评分项或部门口径

可后补，但要单列「待补」：汇报人、日期、协作方角色、预算上限、评分表。

## 处理规则

1. **一个决定。** 卡上只留一个主动作。又要认可成绩、又要立项、又要追加预算时，问用户哪一个是这次必须当场拿到的。
2. **事实和愿望分开。** 「已核实事实」只放用户给过的内容。「希望达成」放决定和成功标准，不混进事实。
3. **不补数字。** 用户没说增长率，就写「待核实」，不写一个看起来合理的百分比。
4. **页数预算。** 封面按 20 秒，请求页按 50 秒，其余内容页按 60 秒。内容页数 = 四舍五入((时长秒数 − 70) / 60)，总页数 = 内容页数 + 2。10 分钟约 11 页，15 分钟约 16 页，30 分钟约 31 页。允许上下 1 页。用户坚持更少页时，记下「压缩」，不要偷偷加页。
5. **场景侧重。**
   - 述职：写明考核周期、个人角色与协作角色，避免把团队结果写成个人独功。
   - 项目方案：写明「不做会怎样」，以及必须比较的备选路线。
   - 投标：写明客户目标和已知评分点；没有评分表时列入待补，不编评分权重。
6. **禁区具体化。** 「别说太细」要改写成可执行句子，例如「不出现未公告的客户名」「不承诺合同外的驻场人数」。

## 输出格式

```
# 汇报任务卡

- 场景：
- 主题：
- 听众与决策权：
- 本次决定（只留一个）：
- 时长：
- 页数预算：
- 成功标准：
- 已核实事实：
  - 事实｜范围｜出处或「用户口述，待补出处」
- 必讲：
- 不讲：
- 约束：
- 待补：
- 假设（仅当有字段是暂定的）：
```

字段为空就写「待补」，不要省略字段名。

## 输出要求

- 决定必须是听众的动作，例如「总监批准增加 1 个实施名额」，不是「让领导了解一下」。
- 已核实事实逐条列出，不合并成一段背景介绍。
- 三种场景用上面的侧重检查一遍，缺场景专属字段就放进待补。
- 卡的末尾用三句话复述：讲给谁、要对方做什么、现在还不能当真的信息是什么。
- 用户确认任务卡之前，提醒下一份应是「叙事骨架」，不要在这一步展开逐页标题。

## 示例（投标，仅演示字段）

- 场景：投标
- 主题：某食品厂冷库巡检数字化
- 听众与决策权：设备部负责人可建议入围，采购负责人决定是否谈判
- 本次决定：同意进入商务谈判
- 时长：20 分钟
- 已核实事实：用户给出「现有巡检靠纸质表，夜班漏检每月约 12 次」；出处待补
- 不讲：不报尚未签约的其他食品客户名称
- 待补：评分表、实施周期上限
