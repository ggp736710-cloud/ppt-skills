# 口述节奏

把已经写好的页面变成能按时讲完的口播。口播跟着页走，不另编一套页面上没有的故事。

## 先读什么

需要任务卡里的时长和决定、叙事骨架的每页秒数、单页措辞的「只说不写」。没有秒数时，先按封面 20 秒、请求页 50 秒、内容页 60 秒暂定，并标明这是暂定。

用户指定念稿或脱稿：

- **念稿**：每页写出完整口播。
- **脱稿**：每页只留开场句、两个停顿点和过渡句，不写长段落。

未指定时，述职和投标用念稿，项目方案用脱稿。

## 语速

按每分钟 220 个汉字估算。某一页的口播字数 = 该页秒数 / 60 × 220。全稿字数与「时长分钟 × 220」相差超过 10%，就删句子，不把语速改成 300 字来凑合。

## 三种场景怎么说

| 场景 | 开头 | 中段 | 结尾 |
|------|------|------|------|
| 述职 | 先说周期和自己负责的范围 | 结果之后立刻说缺口，不先铺垫过程 | 请求只重复任务卡里的那一个决定 |
| 项目方案 | 先说建议选的路线 | 用同一组维度讲放弃的路线 | 说清批准后的第一个动作和负责人 |
| 投标 | 先复述客户目标 | 每讲完一个做法，点回对应的评分点或需求 | 只请求进入下一步，不在口播里临时加承诺 |

## 处理规则

1. **句子短。** 口播单句尽量不超过 28 个字。需要停的地方写成单独一行「停」。
2. **过渡不复用。** 相邻两页的过渡句不能用同一个开头。可用的衔接是：换一个对象、指出差异、把上一页的结果变成下一页的原因。
3. **不增加事实。** 页面和任务卡都没有的数字、客户、奖项，口播里也不出现。
4. **一页只强调一处。** 与单页措辞的「放大」一致。讲到该处时写「看这里」。
5. **时间不够就减页内容，不减请求页。** 优先删原因页里的第三点、计划页里的远期阶段、投标里的公司历史。
6. **动作提示单独成行。** 只使用：停、看这里、看向听众、翻页。不写舞台调度。

## 输出格式

```
# 口述节奏

- 场景：
- 念稿或脱稿：
- 目标时长：
- 口播总字数：
- 与目标字数的偏差：

## 第N页｜页标题｜XX秒｜约XX字

口播正文。

停

看这里

过渡到下一页：

## 时间加总

| 页 | 秒 | 字数 | 是否超字 |
|----|----|------|----------|
| 合计 |  |  | 偏差 x% |
```

脱稿页把「口播正文」换成：

```
- 开场句：
- 停顿点：
- 过渡到下一页：
```

## 输出要求

- 先写完全稿，再算字数。偏差超过 10% 时直接改稿，直到表里的偏差落在范围内，再把结果交给用户。
- 请求页的口播必须包含听众角色、动作和时间。时间未知时说「时间还待你确认」，不说「尽快」。
- 过渡句写在当前页末尾，不单独再做一页过渡稿。
- 不预判听众提问，不写答疑话术。
